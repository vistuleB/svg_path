# Curved-cusp join-side candidate — 2026-10-21

User requested a candidate correction after inspecting case11's raw join circles.
This is separate from the accepted retraced straight-line policy examples.

## Diagnosis and change

`parametric_join_segments` previously classified inner/outer from the cross
product of source endpoint tangents. At the case11 cusps (150,0) and (165,0),
these are exactly (0,1) and (0,-1). Zero cross product bypassed the inner policy.
Round's antiparallel radial tie then used only the offset sign (+9), selecting
sweep True and a tangent-continuous semicircle on the wrong side under the
user's stated cusp-side convention.

The candidate resolves an antiparallel source-tangent tie from agreeing endpoint
curvature signs, allowing one side to be straight. Conceptually, tangents a small
equal arc-length distance before and after a reversal have cross-product sign
equal to the sum of the left-normal curvatures. This supplies the limiting turn
for shared inner/outer dispatch and for Round's antiparallel-radius sweep.
Opposing bends, unavailable curvature and two straight segments retain the
previous offset-sign fallback. Non-tie turns retain the existing cross-product
and endpoint-radius rules. No public options or error variants change.

Round now selects the other semicircle at both case11 cusps: sweep False,
unchanged radius 9 and endpoints (159,0)→(141,0), (174,0)→(156,0).
Miter/MiterClip now honor the existing inner style there: default InnerBevel or
explicit InnerRound. The old inward reversal and near-tie regression tests remain.

## Rescue-revocation fallback — 2026-10-21

Implemented at the user's request. On ForcedParityAmbiguous, compare the
unchanged original split occurrences with the current flags. Simultaneously mark
all still-rescued, originally submerged occurrences incident to any reported
ambiguous vertex. Retry only when at least one flag changed; otherwise return
the original error. All other errors pass through. Original non-submerged pieces
cannot be deleted by this fallback; each retry strictly reduces rescued pieces.
Occurrence lists remain aligned, including repeated traversals of the same edge.

Case11 cusp-only trace: initial 49 deletion flags, ambiguity at vertices 38/45;
retry has 53 flags and succeeds at parity. Exactly four previously rescued
occurrences are revoked. Reconstruction produces two closed cycles: an 8-edge
local loop and a 49-edge main boundary. The enclosing cusp-only contract rejects
two survivors with InternalIToKSubpathCount(2), exposed publicly as
ConstructionFailed. Thus the fallback fixes the parity ambiguity but not the
whole public call. No change to that contour-preservation contract was made.

Evidence: case11-cusp-fallback-trace.json, case11-cusp-fallback-result.json;
draw-case11-cusp-fallback.py validates the four revoked pieces were originally

reconstructed cycles rejected by the API, not a successful returned result.

## Offside reconstruction: prefer less submerged competing routes

The previous offside-only reconstruction kept the upper two-edge route
(parameter span 0.27947922844832046) instead of the lower arc
(0.20614449483356279). Both passed offside classification. Selection used retained
parameter span, skipped runs, then original traversal indices; it did not use
submerged status.

The candidate now computes winding-based submerged status on the existing
pre-offside arrangement. When two partial walks have the same endpoints and
both contain exclusive occurrences, compare the submerged parameter span of
those exclusive occurrences first, preferring less. Shared occurrences cancel.
Ties and non-competing walks retain the previous scoring. This is still a
heuristic for mixed routes, not a general parity/boundary solver, and its mixed
route weighting still depends on source parameterization.

An initial version also preferred omitting submerged attached cycles, producing
14 output contours. Requiring exclusive occurrences on both sides avoids treating
an optional attached cycle as an alternative route.

CC01405 now has 83 segments after offside-only trimming, then one closed
44-segment contour after cusp trimming. Its area is 141959.84850931115, matching
the pinned Cavalier result. The lower radius-16.5 arc survives. The regression
`offside_prefers_non_submerged_cusp_route_test` checks this arc, closedness,
contour count, and area.

## Restrict preference to clean alternatives

returned one 18-segment contour (signed area 0.03987555098556522); minimizing
submerged span returned three contours. A traced comparison chose an entirely
submerged shortcut over a longer mixed route solely because the shortcut had
less submerged parameter span. Thus the mixed-route extension was too broad.

exclusive alternative contains no submerged span. If both contain submerged
