# Gallery

This is a holding area for visual examples that could become a polished README
gallery around `v1.0.0`.

The gallery should show real outputs generated by this package, with minimal
decoration added only to make the geometry readable. Prefer figures that reveal
what the library computes, not abstract marketing images.

Do not try to curate too early. Over-generate candidate figures, inspect them,
then keep only the examples that are visually clear or mathematically
interesting.

## CSG And Fill Rules

- Nested contour CSG table: square doughnut `A` crossed by a narrow `B`, with
  orientation arrows and separate `Nonzero` / `EvenOdd` rows for `union`,
  `intersection`, and `difference`.
- Rectangle pile union: several overlapping rectangles, raw `Nonzero` union,
  then `effects.rounded_corners(..., radius: 6.0)` to show contour-preserving
  cleanup and effects as a pipeline.
- Same geometry under different fill rules: one nested path rendered as
  `Nonzero` and `EvenOdd`, with the path orientation visible.

## Offsets, Bands, And Strokes

- One-sided offsets of a cubic curve at increasing distances, showing how curve
  approximation stays smooth while the distance grows.
- Closed figure-eight band with asymmetric distances, using different colors
  for each output subpath and arrows on all contours.
- Plain stroke examples for open and closed paths: butt, square, and round caps
  on the same input, plus a self-touching closed path.
- A narrow concave shape whose inset collapses into fewer contours, to show
  trimming of unreachable offset sections.

## Effects

- Rounded corners on a rectangle union, before and after, with the original
  rectangles faintly visible.
- Rounded corners on a CSG result containing internal contours, using muted
  colors for inner contours so orientation remains readable.
- A closed one-segment cusp before and after `rounded_corners`, since it is a
  compact example of treating topology rather than only segment count.

## Congruency And Fitting

- Segment congruency examples: line-to-line, arc-to-arc, cubic-to-transformed
  cubic, and a rejected semantic mismatch.
- Point-cloud fit illustration: original points, transformed noisy points,
  fitted similarity transform, and residual error.

## Convex Hull

- Tangled or self-intersecting path with hull overlay, emphasizing that hull is
  a separate operation from fill area.

## Presentation Rules

- All figures should be generated by tests or scripts in the repo.
- README-facing and gallery-facing copies should live on the `markdown-assets`
  branch and be referenced by raw GitHub URLs.
- Preview SVGs for local discussion should be written under `examples/debug/`
  with explicit `width`, `height`, and `viewBox`.
- Use orientation arrows when topology or fill behavior depends on direction.
- Keep text labels short; the README prose should explain the figure.
- It is fine for this file to accumulate many figure ideas before `v1.0.0`;
  the final README gallery can be much smaller.
